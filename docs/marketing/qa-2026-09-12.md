## Onboarding wizard (plan M9, same day)

Walk: `artifacts/qa-frontend/2026-09-12-m9` — **104 scenes, 0 console
errors, 0 overflow** on the second pass. The wizard is one route per
step (`/onboarding/:step`, 13 slugs; bare `/onboarding` resumes at the
saved bookmark), a scrolling step rail + progress bar, one `<Reveal>` per
route, and a Card per step built from the shadcn Form primitives. Read:
`11-onboarding-1-*` (identity, the strict validation on Next, the import
dialog), `12-*` (contact, education with "add another school",
experience with a role added), `14-*` (documents empty / filled),
`13-*` (eligibility + the chosen state, compensation), `15-*` (about,
the self-ID placeholder, preferences), `16-*` (review blank / filled /
the server's `missing[]` rendered verbatim), `17-*` (load error, loading).

The first pass found **21/104 scenes overflowing at 390px** with the
document 464–679px wide, invisible in the pixels and varying with the
current step's title length. Cause: the step rail hid non-current titles
with `sr-only`, which is `position:absolute` — those spans kept their
static position inside the `overflow-x-auto` rail and, being positioned
out of it, widened the document. The link already carries a full
`aria-label`, so the titles are now `hidden sm:inline` on a phone.
Re-walked: 0 overflow.

Independent review (read-only) found no data or safety defect and three
real ones, all fixed before commit: (1) jumping steps via the rail with a
shape-invalid edit silently dropped it — navigation now runs the step's
flush first, shows the errors and stays put; saves are serialized so
Next during an autosave lands after it; (2) the old client-side
`saveMyProfile` (which stamped `onboarding_completed_at`) and the two
legacy single-file uploaders were dead but exported — deleted, so "only
the server marks you complete" is structural; (3) the vendored Input and
Textarea were plain function components, so react-hook-form's
focus-on-error had no ref to focus — both are `forwardRef` now.
